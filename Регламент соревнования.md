# Регламент соревнования

## Цель

Команды строят харнесс кодового агента на базе openJiuwen, который за фиксированный бюджет токенов набирает как можно больше баллов на наборе из 100 задач.

Постановка выросла из задачи индустриальных партнёров Budget-Aware Token Estimation for Agentic AI.

Выигрывает команда, которая лучше всех:

- оценивает заранее, сколько токенов потребует задача, и выбирает самые выгодные;
- распознаёт невыполнимые задачи и не тратит на них бюджет;
- решает задачи экономно: управляет контекстом, числом шагов и выбором модели.

## Задача участников

Харнесс получает список из 100 задач и бюджет токенов и должен набрать максимум баллов за решённые задачи.

- У каждой задачи своя стоимость в баллах. Баллы расставлены случайно и не связаны со сложностью.
- Часть задач невыполнима, часть очень простая.
- Бюджет один на всё: выбор задач, оценку расхода и решение.
- Харнесс видит все 100 задач и их баллы сразу и сам решает, что и в каком порядке решать.
- Задача, не сданная до исчерпания бюджета, не засчитывается.
- Задача, решенная неверно, не засчитывается.

## Модели и учёт токенов

Бюджет задаётся в выходных токенах; 10 входных токенов равны одному выходному.

- Токены рассуждений входят в расход как выходные, независимо от того, в каком поле их возвращает API.
- Кеш провайдера не учитывается: все входные токены считаются полностью.
- Доступны четыре модели: qwen3.8-27b, qwen3.8-27b-noreason, qwen3.6-35b-a3b, qwen3.6-35b-a3b-noreason. Варианты с суффиксом -noreason работают без рассуждений.
- Команда сама выбирает модель и может переключать её на любом вызове по решению своего планировщика.

## Среда выполнения

Харнесс работает в изолированном контейнере, единственный выход в сеть — прокси организаторов.

| Что | Значение |
| --- | --- |
| `LLM_BASE_URL`, `LLM_API_KEY` | адрес и ключ прокси, передаются при запуске в переменных окружения|
| `tasks-dir` | 100 каталогов задач, баллы за задачу в поле reward в task.json |
| Ресурсы | время работы агента ограничено; CPU не более 4 ядра , RAM не более 16 Гб; без GPU |
| Параллельность | до 5 сессий агента одновременно |

- Локальные нейросетевые модели запрещены: обращения к языковым моделям идут только через прокси к четырём разрешённым моделям. Классические методы — регрессия, бустинг — разрешены.

## Наборы задач

Организаторы дают участникам примеры задач. Все задачи в примерах выполнимые.

- **Тренировочный набор** участники собирают сами
- **Финальный набор** скрыт до прогона, формат будет как в примерах задач
- **Ориентировочный состав:** 15–25% невыполнимых

## Сдача решения

Команда выкладывает решение в публичный или приватный git-репозиторий на GitHub или GitFlic. Если репозиторий приватный, нужно дать доступ членам жюри: `promsoft` и `madrugado`. Если у них не будет доступа на момент завершения соревнования, задание проверяться не будет.

Проект при запуске получает в параметрах имя папки с задачами и имя файла для сохраненных решений. Проект должен сохранять файл с решениями после каждого решения. Если агент решил задачу, но не сохранил файл с решениями, задача будет считаться нерешенной.
Как только агент выберет свой лимит токенов, LLM прокси будет переставать отвечать на запросы, запуск будет принудительно завершаться.


\
Будут заданы переменные окружения\
`OUT` - выходной файл\
`TASKS` - каталог с задачами\
`LLM_BASE_URL` - адрес llm-прокси\
\`LLM\_API\_KEY\` - ключ (у проверяющих будут свои ключи)

Докер-контейнер будет запускаться командой:\
```
mkdir -p "$OUT" && chmod 777 "$OUT"

docker build -t "hack:latest" && \
timeout -k 1000s 1h docker run --rm --name "run-${TEAM}" \
  --network hack-net \
  -e LLM_BASE_URL -e LLM_API_KEY \
  -v "$TASKS:/data/tasks:rw" \
  --read-only --tmpfs /tmp:rw,size=2g -e HOME=/tmp \
  --cap-drop ALL --security-opt no-new-privileges \
  --cpus 8 --memory 16g --pids-limit 512 \
  --workdir /app --entrypoint python \
  "hack:latest" \
  /app/run_agent.py --tasks-dir /data/tasks
```

в каталоге каждой задачи нужно создать файл answer.txt

В репозитории:

- Dockerfile харнесс на базе openJiuwen
- все файлы, нужные для сборки и работы;
- README.md с описанием всех неочевидных деталей

Оценивается последний коммит на момент закрытия соревнования, последующие коммиты игнорируются. Время сборки Docker-образа ограничено. Версию openJiuwen команда выбирает сама — любую, с которой образ собирается.

Ограничения:

- репозиторий — меньше 100 МБ без учёта папки `.git`;
- собранный образ — меньше 4 ГБ по выводу команды `docker images --format "{{.Repository}}:{{.Tag}} -> {{.Size}}"`;
- если решение состоит из нескольких образов, их размеры складываются, и сумма должна быть меньше 4 ГБ.
- таймаут сборки образа 1000s
- таймаут работы образа 1 час
-

openJiuwen, например, можно поставить из PyPI: `pip install openjiuwen==0.1.19`

Уточнения:

- README.md описывает сборку и запуск, способ оценки расхода и поиска невыполнимых задач, собранные траектории.
- Версии зависимостей и тег базового образа зафиксированы.
- В репозитории нет ключей API: ключ прокси передаётся при запуске.
- Всё, что скачивается при сборке (пакеты, данные, веса оценщика), попадает в образ и учитывается в лимите 4 ГБ. Скачивать что-либо при запуске нельзя.

## Порядок оценки

Решение проходит четыре этапа; вылет на любом из первых трёх означает незачёт.

1. **Проверка безопасности** Docker-образа до запуска, с помощью LLM.
2. **Сборка** образа. Не собрался — команда снимается с соревнования.
3. **Отборочный прогон** на минимальном наборе из двух выполнимых задач: харнесс должен решить обе в пределах выданного бюджета.
4. **Прогон на полном наборе**: набрать как можно больше баллов за отведённое время и бюджет токенов. Баллы начисляются за задачи, прошедшие скрытые тесты.

При равенстве баллов побеждает команда, потратившая меньше токенов. Время работы агента ограничено одним часом.
